## Product: Yin Yang Launcher

An Android home-screen replacement app (yin/yang branding = light/dark duality) combining a calm home screen, a customizable widget dashboard, and screen-time/wellbeing insights.

Features below are grouped into execution phases, ordered so each phase only depends on ones before it. Update Structure/Commands as each phase lands.

**From-Apps widget pitfalls (if touching this code):** a freshly created `AppWidgetHostView` renders blank for many widgets because their RemoteViews pick a layout by declared size, which defaults to 0×0 dp until told otherwise — `AppWidgetPlatformView` works around this with a one-shot `OnGlobalLayoutListener` that calls the (deprecated but still functional) 5-arg `updateAppWidgetSize` once Flutter's `AndroidView` has a real layout size. `AppWidgetHost.startListening()`/`stopListening()` are wired to `MainActivity.onStart`/`onStop`.

**Weather tile pitfalls (if touching this code):** `LocationAccuracy.low` uses the network/fused provider, which doesn't respond to `adb emu geo fix` on an emulator — use `.high` with a time limit. The `geocoding` package's native reverse-geocode call blocked the Android main thread indefinitely on the test emulator (no Play Services geocoder backend) and caused an ANR; it was replaced with a timeout-bounded HTTP call instead.

**Known limit, not in scope:** Focus Mode can only gate launches this launcher makes. Native From-Apps widget taps (their PendingIntents fire inside `AppWidgetHostView`), notifications, and the recents screen all bypass it. Blocking those would need an `AccessibilityService` or similar app-wide enforcement, which is a much bigger permission ask.

8. ✅ **Focus schedules** — built on `flutter_local_notifications` (+ `timezone`, `flutter_timezone`; the user chose a plugin over a native `AlarmManager` bridge). It needs core library desugaring in `android/app/build.gradle.kts`, its `ScheduledNotificationReceiver`/`ScheduledNotificationBootReceiver` in the manifest (reboots and app updates re-arm reminders), and `SCHEDULE_EXACT_ALARM` + `RECEIVE_BOOT_COMPLETED`. `lib/services/focus_schedule_service.dart` persists `FocusSchedule`s (`focus_schedules`: name, weekdays, start time, length, strict, enabled) and after every write rebuilds all reminders from scratch (`cancelAll`, then one weekly `zonedSchedule` per enabled schedule and day, id `index * 10 + weekday`, `DateTimeComponents.dayOfWeekAndTime`; first fire from `nextWeekdayTime`, tested). `FocusScheduleService.init()` runs unawaited from `main` (time zones, plugin, cold-start tap); until it has run (tests) the plugin is never touched. Tapping "Time to focus · <name> · 1 h · Tap to start" calls `startFromReminder`, which starts that schedule's timed session unless one is already running (tested). Reminders are exact only if the exact-alarm grant (user-granted on Android 14+) exists when they're scheduled, otherwise inexact (Android allowed a ~3-minute window). The editor asks for notifications + exact alarms before saving, but the exact-alarm request just opens a system screen and returns, so `FocusSchedulesPage` also calls `refreshReminders` on resume. UI (`lib/mind_space/focus_schedules.dart`): a Schedules row on the Focus Mode page → list with on/off switches → editor (name, M-S day circles, `showTimePicker`, 15 min-4 h length, strict switch, delete). **Strict mode:** `FocusModeService.start(strict:)` (new `focus_mode_strict` key, only kept for timed sessions; tested) hides every early exit: the APPS sheet shows "Strict session · ends at 1:44 PM" instead of "Exit focus mode", and `FocusQuickActions` drops Stop. The Timer's duration sheet gained a strict switch too, so `showFocusDurationSheet` now returns `({Duration duration, bool strict})`. Widget test: a strict session offers no exit in either place. Verified live: a schedule saved for 12:44 asked for notifications then exact alarms; after coming back the alarms were exact (`window=0`, today and the following weekdays); "Time to focus" posted at 12:44:01, and tapping it started a strict 1 h session on Home with no exit in the APPS sheet. Deleting the schedule removed all its alarms
9. ✅ **Reflect tab** — a Now/Reflect `SegmentedToggle` at the top of Awareness. Reflect (`lib/mind_space/reflect_view.dart`) shows yesterday's screen time and pickups, a bar per day for up to 14 days (today faded, as it's partial), and a one-line `trendSummary`: the last (up to) 7 full days against the ones before, "Holding steady at about X a day" within ±10%, otherwise "Down/Up N% from the days before". `computeDailyTotals` runs `computeMindSpaceTotals` per calendar day and drops leading days with no events, since Android only keeps a few days to a couple of weeks of usage events (a session spanning midnight is lost; fine for a daily trend). The panel queries 14 days only while Reflect is showing, otherwise just today. **Productive apps** (`lib/services/productive_apps_service.dart`, `mind_space_productive_apps`): a row at the bottom of Awareness opens task 2's picker, and `withoutProductive` drops those apps' foreground/background events (unlocks are kept, so pickups still count) before every Mind Space computation. Tested (`test/reflect_test.dart`: per-day split, trend wording, productive filter) plus a widget test (a productive app's time and row disappear; Reflect shows yesterday). Verified live: marking the launcher itself productive dropped today from 1h 47m to 3m and yesterday from 1h 40m to 13m; Reflect showed the emulator's two days of data and "Not enough history yet to see a trend."

## Structure

- `lib/main.dart` — entry point; gates between `OnboardingFlow` and `LauncherShell` on the persisted onboarding flag
- `lib/shell/` — the 5-panel swipe navigation shell
- `lib/panels/` — the 5 panel screens (Home, My Space, Mind Space, App Drawer, Spotlight Search)
- `lib/onboarding/` — first-run flow (steps, phone mockup, wallpaper/segmented-toggle pickers)
- `lib/my_space/` — My Space-specific widgets (Add New Tile sheet, built-in tile catalog, tile chrome); `lib/my_space/tiles/` holds the per-kind tile bodies (Notes, Todo, Weather, App Folder, From-Apps)
- `lib/settings/` — Settings sheet opened by long-press on Home (Phase 5)
- `lib/mind_space/` — Mind Space tool UI (Phase 7): the Action tab, the one-time tool explainers, the tool pages, the Mindful Pause overlay, Focus Mode's start sheet and session screen, Mindful Timer's group editor and session-length sheet, Mindful Break's block screen, Focus schedules' list and editor, and the Reflect view
- `lib/search/` — shared app search/filter logic and UI, used by App Drawer, Spotlight Search, and the App Folder/From-Apps picker sheets; `app_picker_sheet.dart` picks one app (App Folder tile, Mindful Break); `visible_apps.dart` applies customizations and breaks to the drawer's and Spotlight's lists; `app_multi_picker_sheet.dart` is the checkbox picker for any set of apps (Focus Mode essentials, and Phase 7's Mindful Pause/Timer/Productive apps)
- `lib/state/` — `AppSettings` (theme/layout/wallpaper), exposed via `AppSettingsScope` (`InheritedNotifier`)
- `lib/services/` — platform-channel and persistence services (installed apps, onboarding flag, launcher role, My Space tiles, weather, app widgets, usage stats, Focus Mode, Mindful Pause, Mindful Timer, Mindful Break, Focus schedules via `flutter_local_notifications`, productive apps, per-app pins/hides/renames, Home's dock); `installed_apps_service.dart`'s `launch` consults `focus_mode_service.dart` before opening an app — the one choke point all launch call sites (App Drawer, Spotlight Search, App Folder tile) route through
- `lib/models/` — plain data models (`HomeLayoutMode`, `MySpaceTile`, `TileKind`)
- `lib/widgets/` — small shared widgets (`SegmentedToggle`) and `launchApp`, the UI-side launch helper that explains Focus Mode refusals
- `android/app/src/main/kotlin/.../MainActivity.kt` — native `RoleManager.ROLE_HOME` MethodChannel bridge (`yinyang.launcher/role`: `requestHomeRole`, `isDefaultLauncher`, `openHomeSettings`, `defaultCommsPackages`, `defaultDockPackages`) plus the `yinyang.launcher/app` channel (`restart`, `openAppInfo`, `openClock`); wires up `AppWidgetHostBridge`'s lifecycle/activity-result routing and attaches `UsageStatsBridge` and `MindfulTimerBridge`
- `android/app/src/main/kotlin/.../AppWidgetHostBridge.kt` — native `AppWidgetHost`/`AppWidgetManager` bridge (`yinyang.launcher/appwidget` channel + `yinyang.launcher/appwidget_view` platform view) for the From-Apps tile
- `android/app/src/main/kotlin/.../MindfulTimerBridge.kt` — Mindful Timer's in-process session countdown and "Time's up" `SYSTEM_ALERT_WINDOW` overlay (`yinyang.launcher/timer` channel: `canDrawOverlays`, `requestOverlay`, `startSession`)
- `android/app/src/main/kotlin/.../UsageStatsBridge.kt` — native `UsageStatsManager`/`AppOpsManager` bridge (`yinyang.launcher/usage` channel) for Mind Space
- `test/` — widget tests; app startup is async (SharedPreferences), so tests use `SharedPreferences.setMockInitialValues` and `pumpAndSettle`
- `android/`, `ios/`, `macos/`, `linux/`, `windows/`, `web/` — platform runner projects generated by Flutter tooling; rarely need manual edits
- Dart SDK constraint: `^3.13.3` (see `pubspec.yaml`)
- `graphify-out/` — generated knowledge-graph artifacts from `/graphify`; not app code, gitignored
